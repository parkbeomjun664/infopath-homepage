### 3. 화면 개선

**/about 재구성** — 가장 크게 손본 페이지

전에는 회사 개요 · 수행 실적 · 사업자 정보가 **모두 같은 회색 테두리 격자**였습니다.
법적 고지인 사업자 정보가 실적과 같은 비중으로 읽히면 무엇이 중요한지 알 수 없습니다.

→ 숫자 띠로 규모를 먼저 보여주고, 실적은 배경을 바꿔 띄우고, 사업자 정보는 테두리를 걷어내 가장 조용하게.

| 사안 | 결정 | 이유 |
|---|---|---|
| 회사 개요 숫자 | **카운트업 연출 제거** | 회사 개요는 성과 자랑이 아니라 사실 고지. 움직이면 가벼워 보임 |
| 숫자 표기 | 라벨을 위, 숫자와 단위를 크기로 분리, 세로 구분선 | 국내 대기업 회사소개 페이지의 표기 관습 |
| 연혁 | **가로로 눕힘** | 읽혀야 하는 건 각 마디의 상세가 아니라 방향 하나. 세로로 세우면 화면 두 개를 먹음 |
| 작은 부가 설명 | **전부 제거** (사용자 요청) | 단, `/infolink`의 note 3개는 남김 — 「현재 구현은 여기까지」를 밝히는 고지라 지우면 도면 전체가 구현된 것으로 읽힘 |

**빈 공간 정리**

- FAQ · 개인정보처리방침 · 문의 → **좌우 2단**으로 전환. 넓은 화면에서 오른쪽 40%가 비어 있었음
- `/infolink` 현장 문제 → 3열. **subgrid**로 카드 간 행을 맞춰 초록 구분선이 한 줄에 놓이게 함
- 세로 여백은 120 → 96px로 줄였다가 **다시 120px로 복원**. [reference-analysis.md](reference-analysis.md)의 조사 결론(176px 권장)과 정반대로 가 있었고, 가로 공백은 따로 해결됐으므로

**/contact — 두 번 고침**

1차에서 안내를 왼쪽, 폼을 오른쪽에 뒀는데 **판단 착오**였습니다. FAQ·방침에서 쓴 배치를 그대로 가져왔지만, **그 둘은 읽는 페이지고 여기는 쓰는 페이지**입니다.
→ 폼을 왼쪽 본자리로(시작 위치 548 → 184px). 로고·제목과 같은 세로선에 맞음.

「무엇을 적어주시면 되나요」 목록도 옆에서 자리를 먹길래 **입력란 포커스 힌트로 이동**.
라벨 줄 오른쪽에 띄워 폼이 들썩이지 않게 했고(위치 변동 0px), `display:none` 대신 투명도만 내려 화면 낭독기에는 읽히게 함.

### 4. 고객사 로고 띠

삼성SDS 화면을 참고해 가로 무한 슬라이드를 만들었습니다.

**구현** — CSS만. 같은 목록을 짝수 벌 이어 붙이고 정확히 절반만큼 밀면 이음매가 보이지 않음.
JS가 없어 탭을 벗어나면 브라우저가 알아서 멈춤. 호버 시 정지 + 그림자, `prefers-reduced-motion` 대응.

**로고 확보 과정**

1. "로고 파일이 없다"고 판단 → **틀렸음.** 회사소개서 PDF 6페이지에 들어 있었음
2. 헤드리스 브라우저가 PDF를 렌더링하지 않고 내려받음 → **pdf.js로 캔버스에 직접 그려** 해결
3. 페이지를 12배로 렌더링 후 축소 → 리샘플이 두 번 겹쳐 계단이 생김
4. **PDF 안의 이미지를 그대로 추출**하는 방식으로 변경 → 눈에 띄게 깨끗해짐

**확인된 한계**

| 로고 | PDF 안 원본 크기 |
|---|---|
| 동우화인켐 | 186 × 33 |
| TUNGHSU GROUP | 155 × 55 |
| SEMV | 184 × 57 |
| SEMB | 409 × 58 |

화면에 64px로 띄우는데 원본이 33~58px. **더 선명해질 방법이 없습니다.**
동우화인켐 공식 사이트 로고는 242×30으로 더 작았고, TUNGHSU 사이트는 접속 불가.
Flate 이미지 4개는 로고가 아니라 JPEG의 투명도 마스크였음.
→ **고객사 CI 원본을 받아야 해결됩니다.**

## 이 프로젝트의 원칙

작업하면서 반복해서 적용한 기준입니다.

1. **확인되지 않은 값은 쓰지 않는다.** 추측으로 쓴 문장은 곧 회사의 약속이 됨
2. **비어 있으면 자리를 비우지 말고 섹션을 숨긴다.** 빈 값은 정보가 아니라 미완성 신호
3. **적어둔 것과 실제가 다르면 그게 위반이다.** 회신 기간, 보관 기간, 방침 모두 해당
4. **코드 밖의 위험을 먼저 본다.** 같은 DNS의 회사 메일, 고객사 로고의 상표권, 공개된 사내 도면
