포지셔닝이 사이트 구조를 결정합니다

"플랫폼 보유 + 기업별 구축"이라는 위치는 순수 SI와 패키지 제품사 사이입니다. 이 차이가 곧 설득 논리가 됩니다 — SI는 실적 수로, 제품사는 기능 목록으로 증명하지만, INFOPATH는 "이미 검증된 것을 재사용하므로 싸고 빠르다"는 구조적 이점으로 증명해야 합니다.

그래서 이번 개정에서 메인 페이지의 뼈대를 바꿨습니다. Rev.1의 "데이터 단절" 화법은 SI·컨설팅의 일반 화법이라 INFOPATH의 차별점을 담지 못합니다. 대신 도입 장벽(비용·시간·맞춤)을 제기하고 각 장벽에 플랫폼 재사용으로 답하는 구조로 재구성했습니다. → 04장

브랜드 자산에서 추출한 팔레트

제공된 로고와 배경 이미지의 픽셀을 직접 분석해 색을 뽑았습니다. Rev.1의 페트롤·앰버 제안은 폐기합니다 — 실제 브랜드는 네이비+그린+애저 체계이고, 청록 계열은 어느 자산에도 없습니다.

여전히 미해결

infopath.co.kr은 아직 아이네임즈 주차 페이지이고 HTTPS도 열려 있지 않습니다. 도메인을 Vercel로 옮길 때 MX 레코드는 절대 건드리면 안 됩니다 — 그룹웨어 메일이 즉시 끊깁니다. 절차는 docs/deploy.md에 별도로 정리했습니다.

왜 산업이 아니라 솔루션을 최상위로 두는가

두 레퍼런스 모두 INDUSTRY가 첫 메뉴입니다. 업종별 실적이 두텁게 쌓인 회사에서는 옳은 선택입니다. 하지만 INFOPATH는 아직 공개 가능한 업종별 실적이 확인되지 않았고, 강점은 업종 커버리지가 아니라 플랫폼 재사용이라는 방식 자체에 있습니다.

실적이 없는 업종 메뉴를 6개 세워두면 클릭했을 때 빈 페이지가 나오고, 그 순간 신뢰를 잃습니다. 그래서 산업은 독립 메뉴에서 내리고 /solution 안의 "적용 가능 업종" 섹션으로 통합했습니다. 실적이 쌓이면 그때 승격시키면 됩니다.

04

메인 구성

1차 구현 범위는 S1~S4, S8입니다. S5·S7은 컴포넌트만 만들고 비활성, S6은 2차로 미룹니다.

S1
Hero — 이슈 제기

슬라이더 없는 단일 화면. 배경은 제공된 INFOLINK 이미지. 카피 3안을 모두 코드에 넣고 content/site.ts의 HERO_VARIANT로 전환합니다.

A안 · 현재 적용 MES 도입에 필요한 건 예산이 아니라 순서입니다 검증된 플랫폼과 AI 기반 설계로, 필요한 것부터 시작합니다
B안 스마트팩토리는 대기업의 것이라는 말, 이제 맞지 않습니다 [초안] 검증된 MES 플랫폼을 현장 규모에 맞춰 구축합니다
C안 대기업 MES를 중소 제조현장의 크기로 [초안] 이미 검증된 플랫폼 위에서, 필요한 모듈만 골라 시작합니다

공통 영문 서브 슬로건 — Start Small, Run Smart

S2
Challenge — 도입의 세 가지 벽

Rev.1의 "수집/분석/운영 단절"을 폐기하고 도입 장벽으로 교체했습니다. 방문자가 실제로 막히는 지점에서 출발해야 다음 섹션의 해법이 설득력을 얻습니다.

Copy MES 도입을 막는 세 가지 벽 01 비용의 벽 — 견적을 받아보면 예산 밖입니다
02 시간의 벽 — 도입에 1년, 그사이 현장은 그대로입니다
03 맞춤의 벽 — 우리 공정에 맞추려면 처음부터 다시 만들어야 한다고 합니다
S3
Solution — 각 벽에 1:1 대응

S2의 세 벽과 순서·개수를 정확히 맞춥니다. 카드마다 어떤 벽에 답하는지 명시해 논리 연결을 눈에 보이게 합니다.

Copy 세 개의 벽을 넘는 세 가지 방법 비용 → 검증된 플랫폼 재사용 — 신규 개발이 아니라 검증된 MES에서 출발
시간 → 필요한 모듈부터 단계 도입 — 효과 큰 지점부터 순차 적용
맞춤 → AI 기반 공정 맞춤 — 설정 수준에서 맞추고 코드를 다시 쓰지 않음
S4
Industry — 적용 가능 업종

6개 업종 타일. 개별 페이지로 연결하지 않고 /solution 앵커로 보냅니다. 빈 페이지를 만들지 않기 위한 선택입니다.

Copy · 초안 업종이 다르면 공정이 다르고, 필요한 시스템도 다릅니다 전기전자·부품 / 자동차·부품 / 화학·소재 / 기계·금속가공 / 식음료·제약 / 포장·인쇄
S5
Numbers — 실적 지표 · 비활성

컴포넌트는 만들되 SECTIONS.metrics = false로 렌더링하지 않습니다. 실제 수치 확보 시 플래그만 켜면 됩니다.

S6
Case — 구축사례 · 2차

공개 가능한 사례가 확인되지 않아 1차 범위에서 제외했습니다.

S7
Clients — 고객사 로고 · 비활성

SECTIONS.clients = false. 로고 무단 게재는 실제 분쟁 사유이므로 사용 동의 확보 전까지 켜지 않습니다.

S8
CTA — 도입 문의

네이비 배경 전폭 배너. 선택지를 늘리지 않고 단일 행동으로 수렴시킵니다.

Copy 우리 공장에는 무엇이 필요할까요? 공정 현황을 알려주시면 적용 가능한 범위와 예상 일정을 정리해 회신드립니다.

법적 필수

문의 폼은 개인정보를 수집하므로 수집·이용 동의 절차와 개인정보처리방침이 필수입니다(개인정보보호법 제15조). 푸터 사업자 정보 표기도 의무입니다. 두 항목은 오픈 전 반드시 채워야 하며, 현재 사업자 정보는 미확보 상태입니다(09-Q3).

06

디자인 시스템

모든 색이 브랜드 자산에서 나옵니다. 임의 선정한 색은 없습니다.

Color · 구현 완료

tailwind.config.ts에 고정 팔레트(navy/green/azure/steel)를 정의하고, 그 위에 CSS 변수 기반 시맨틱 토큰(bg, fg, line, cta…)을 얹었습니다. 컴포넌트는 시맨틱 토큰만 참조하므로, 색을 바꿔도 컴포넌트를 수정할 필요가 없습니다.

CTA 색상 · 선택 필요

세 안을 모두 구현해두었습니다. content/site.ts의 CTA_VARIANT 한 줄로 전체가 바뀝니다.

green · 현재#48A830로고 인피니티 마크. 브랜드 일치도 최상
azure#1878C0배경 하이라이트. 네이비와 동계열이라 차분함
amber#C87A14대조군. 유도력 최대이나 브랜드 자산에 없음

Typography · 구현 완료

역할설정비고

알려진 부담

Pretendard 가변폰트 원본이 약 2MB입니다. 해시 캐시로 재방문 비용은 없지만 첫 방문은 무겁습니다. Phase 4에서 공식 동적 서브셋(unicode-range 92조각)으로 전환을 검토합니다. 현 단계에서는 단일 파일 유지가 관리상 안전합니다.

Components · Radius / Motion

  • 라운드 2~3px — 제조 IT 톤에 맞춰 과한 둥근 모서리를 배제했습니다.
  • 모션은 스크롤 진입 시 24px 상승 + 페이드 400ms 하나로 제한. prefers-reduced-motion 대응 완료.
  • 상태색(정상/주의/경고)은 CTA·브랜드색과 분리해 별도 정의했습니다.

진행 현황

Phase 1은 6개 작업으로 나뉘며, 작업 1~3 완료 후 확인을 받기로 했습니다.

  1. ✓Next.js App Router + TypeScript + Tailwind + next-intl 셋업완료
  2. ✓tailwind.config.ts 컬러 토큰 · CTA 3안 비교 가능완료
  3. ✓Pretendard 가변폰트 로컬 적용완료
  4. —공통 컴포넌트 · Button, Card, SectionLabel, Header(언어 전환), Footer대기
  5. —content/ 데이터 레이어 + messages 분리일부 완료
  6. —메인 S1~S4, S8 골격 구현대기

작업 5는 문의 폼과 검증 페이지를 띄우기 위해 메시지 구조와 site.ts를 먼저 만들어 두었습니다. 확정하신 히어로 3안과 S2 세 벽 카피는 이미 content/messages/ko.ts에 들어가 있고, 영문도 함께 작성했습니다.

확인 필요

Rev.1의 Q1·Q2·Q3·Q8·Q10은 해소되었습니다. 남은 항목과 새로 생긴 항목입니다.

Q1

CTA 색상 — green / azure / amber 중 무엇으로 갈까요? 검증 페이지에서 세 안을 나란히 볼 수 있습니다. 기본값은 green입니다.

작업 4 전
Q2

히어로 카피 — A / B / C 중 확정안은? 현재 A안이 적용되어 있습니다. B·C안의 서브카피는 제가 쓴 초안이라 검수가 필요합니다.

작업 6 전
Q3

사업자 정보 — 대표자명, 사업자등록번호, 본사 주소, 대표전화. 푸터 법적 표기 의무 항목입니다.

Phase 2
Q4

적용 업종 6종 — 현재 목록은 제 초안입니다. 실제 구축 실적이 있는 업종으로 교체가 필요합니다.

Phase 3
Q5

INFOLINK 플랫폼 상세 — /solution 페이지를 채우려면 모듈 구성(생산·설비·품질 등), AI 적용 지점, 실제 절감 효과 수치가 필요합니다.

Phase 2
Q6

실적 수치 — 설립연도, 누적 프로젝트 수, 임직원 수. 확보되면 S5 섹션 플래그를 켭니다.

Phase 3
Q7

고객사 로고 사용 동의 — 확보되면 S7 플래그를 켭니다. 계약상 비공개 조건이 있는지도 확인이 필요합니다.

Phase 3
Q8

Resend 계정 — 계정 생성 및 API 키 발급이 필요합니다. 도메인 인증(SPF/DKIM) 시 기존 그룹웨어 SPF와 합쳐야 합니다. 별도 추가 시 회사 메일이 스팸 처리될 수 있습니다.

Phase 2
Q9

영문 페이지 노출 시점 — 라우팅은 준비됐고 영문 문구도 초안이 있습니다. 1차 오픈에 포함할지, 국문만 먼저 열지 결정이 필요합니다.

Phase 4
Q10

회사로고.bmp — 루트에 있던 세 번째 파일입니다. 용도가 무엇인지, 사용해야 하는지 알려주십시오. 현재는 보관만 하고 사용하지 않았습니다.

작업 4 전
다음 단계

Q1(CTA 색상)만 정해주시면 작업 4~6(공통 컴포넌트 → 메인 골격)으로 바로 넘어갑니다. Q2는 작업 6 전까지만 주시면 되고, 나머지는 현재 초안·비활성 상태로 두고 진행할 수 있습니다.
