# MICube 실측 — 스크롤 반응 · 구조 · 크기

대상: https://www.micube.co.kr/

## ⚠️ 측정 방법에 대한 고지

**chrome-devtools MCP가 이 세션에 연결되어 있지 않아 브라우저로 측정하지 못했습니다.**
대신 사이트의 HTML · CSS · JavaScript를 직접 내려받아 **소스에 선언된 값을 읽었습니다.**

받은 파일: `base.css` `common.css` (합 600KB) · `script.js` 외 15개 JS (합 627KB) · `scrollAni.js` · `nav6/style.css`

| 표기 | 뜻 |
|---|---|
| `[측정]` | 소스에 명시된 값을 그대로 읽음 |
| `[기본값]` | 소스에 미지정 → 라이브러리 기본값 |
| `[미측정]` | 브라우저 없이는 확인 불가 |

정적 분석으로 **스크롤 애니메이션의 이동 거리·이징·트리거 지점은 정확히 나왔습니다.**
반면 **헤더 상태 변화와 computed style은 못 얻었습니다.** 아래에 항목별로 명시했습니다.

---

## 1. 스크롤 반응

### 1-1. 사용 라이브러리 [측정]

**GSAP 3.6.0 + ScrollTrigger** (지연 로드). 제어는 전부 `views/res/js/utils/scrollAni.js`에 있습니다.
요소에 `data-scrollani="슬라이드종류"` 속성을 붙이는 방식입니다.

### 1-2. 이동 거리 [측정]

CSS에 초기 상태가 선언되어 있고, GSAP이 이를 0으로 되돌립니다.

| 종류 | 초기 상태 | 이동 거리 |
|---|---|---|
| `slideUp` | `opacity:0; transform:translate3d(0, 30px, 0)` | **↑ 30px** |
| `slideDown` | `opacity:0; transform:translate3d(0, -30px, 0)` | ↓ 30px |
| `leftToRight` | `opacity:0; transform:translate3d(-30px, 0, 0)` | → 30px |
| `rightToLeft` | `opacity:0; transform:translate3d(30px, 0, 0)` | ← 30px |
| `fadeIn` | `opacity:0` | 없음 |
| `scaleDown` | `transform:scale(1.1)` | 1.1 → 1.0 |
| `slideup_st2` | `opacity:0; transform:translate3d(100px, 80px, 0)` | 대각 |

**기본 이동 거리는 30px입니다.** 전부 `translate3d`를 씁니다.

### 1-3. 지속 시간 [기본값]

```js
slideUp.to(element, { opacity: "1", y: "0", delay: aniDelay, ease: "power1.out" });
```

`.to()`에 **`duration`이 지정되어 있지 않습니다.** → GSAP 기본값 **0.5s (500ms)** 적용.

### 1-4. 이징 [측정]

| 종류 | ease | CSS 근사 |
|---|---|---|
| `slideUp`, `slideup_st2` | `power1.out` | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` (easeOutQuad) |
| 나머지 전부 | `power1.inOut` | `cubic-bezier(0.455, 0.03, 0.515, 0.955)` |

`power1`은 2차(quad) 곡선입니다. **감속이 완만합니다.**

### 1-5. 트리거 지점 [측정]

```js
scrollTrigger: { start: "top 90%", end: "bottom 0%", toggleActions: "play none none reverse" }
```

| 종류 | start | 뜻 |
|---|---|---|
| 대부분 | `top 90%` | 요소 상단이 뷰포트 90% 지점 도달 = **화면에 10% 들어오면** 재생 |
| `drawLine` | `top 85%` | 15% 들어오면 |
| `toggleClass` | `top 65%` | 35% 들어오면 |

**`toggleActions: "play none none reverse"`** — 위로 되감으면 **애니메이션이 역재생**됩니다.
즉 **한 번만 재생하지 않고, 스크롤을 오르내릴 때마다 반복**됩니다.

### 1-6. stagger [미측정]

`data-scrollani-delay` 속성으로 요소별 지연을 주는 구조입니다.

```js
var aniDelay = delay || element.getAttribute("data-scrollani-delay") || '0';
```

그러나 **메인 페이지 HTML에 이 속성도, `data-scrollani` 속성도 하나도 없습니다.**
JS가 런타임에 붙이는 구조라 **간격 값은 브라우저 없이 확인 불가**합니다.

### 1-7. 패럴랙스 [측정 — 없음]

**micube에는 패럴랙스가 없습니다.**
전체 JS 627KB에서 `parallax` 문자열은 **1회**(라이브러리 잔재)뿐이고, 구현이 없습니다.
`scrollAni.js`에도 스크롤 위치 연동 이동은 없습니다.

> 우리가 히어로에 넣은 패럴랙스(-0.30 / -0.15)는 **이 참고 사이트에 근거가 없습니다.**

### 1-8. 헤더 스크롤 상태 [미측정]

`nav6/style.css`에 스크롤 상태 전환 규칙이 없고, jQuery 번들에 묻혀 있어
**임계값 · height · background · box-shadow · transition 값을 얻지 못했습니다.**
이 항목은 브라우저 측정이 반드시 필요합니다.

### 2-5. 카드 그리드 [측정 — 해당 없음]

격자 그리드가 아니므로 **열 수 · gap · 종횡비를 측정할 대상이 없습니다.**

# 적용 제안

## 제안 1 — 이징 변경 `검토 필요`

우리 `cubic-bezier(0.16, 1, 0.3, 1)`은 끝에서 급격히 감속하는 곡선입니다. 또렷하지만 살짝 튀는 느낌이 납니다.
micube의 `power1.out`은 완만해서 **더 조용합니다.**

| 안 | 이징 | 성격 |
|---|---|---|
| 1-A | 현행 유지 | 또렷함. 지금 히어로 시퀀스와 통일됨 |
| 1-B | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` | micube와 동일. 차분함 |

**"부담 없이"라는 톤에는 1-B가 맞습니다.** 다만 히어로 진입 시퀀스도 같이 바꿔야 통일됩니다.

## 제안 2 — 지속시간 `선택`

700ms → **600ms**를 제안합니다. micube 500ms와 LS 700ms의 중간입니다.
섹션이 적어 스크롤이 빠르게 지나가므로 500ms가 더 나을 수도 있습니다.

## 제안 3 — 트리거 시점 앞당기기 `권장`

현재 `threshold: 0.15` + `rootMargin: 0px 0px -8% 0px`는 요소가 꽤 들어와야 재생됩니다.
빠르게 스크롤하면 **이미 화면 중앙에 온 요소가 그제서야 나타나** 어색합니다.

```
현재:  threshold 0.15,  rootMargin '0px 0px -8% 0px'
제안:  threshold 0,     rootMargin '0px 0px -10% 0px'   → micube의 "top 90%"와 동등
```

## 제안 4 — 되감기 반복은 채택하지 않음 `권장`

micube는 `toggleActions: "play none none reverse"`로 스크롤을 오르내릴 때마다 반복합니다.
**우리는 1회 재생 후 `unobserve`를 유지하기를 권합니다.**
B2B 사이트에서 위아래로 훑는 사용자에게 요소가 계속 사라졌다 나타나면 읽기를 방해합니다.

## 제안 5 — 패럴랙스 재검토 `판단 필요`

**참고 사이트 두 곳 모두 패럴랙스를 쓰지 않습니다.** (LS도 `fade-in-from-bottom`뿐)
우리 히어로의 패럴랙스는 지시하신 사양이므로 유지가 기본이지만, **참고 사이트에는 근거가 없다**는 점만 기록합니다.

| 안 | 내용 |
|---|---|
| 5-A `기본` | 현행 유지 — 지시하신 사양 |
| 5-B | 다이어그램(−0.30)만 남기고 배경(−0.15) 제거 |
| 5-C | 전부 제거 — 참고 사이트와 동일 |

## 제안 6 — 브레이크포인트 `조치 불필요`

micube의 992 / 768 / 544는 Bootstrap 계열입니다. 우리는 Tailwind 기본(640/768/1024/1280)을 쓰고 있고
**둘 다 업계 표준이라 굳이 맞출 이유가 없습니다.** 현행 유지를 권합니다.

## 제안 7 — 섹션 패딩 `이미 제안됨`

`docs/reference-analysis.md`의 **제안 A**(120 / 176px)와 동일한 결론입니다. 중복 제안하지 않습니다.
