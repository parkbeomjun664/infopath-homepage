## 2순위 — 콘텐츠가 비어 있어 "초안"으로 표시된 것

### 2-1. 회사 소개 본문

`/about` 페이지가 지금은 상호·도메인·이메일만 있는 껍데기입니다.

- 회사 소개 글 (5~10줄)
- 설립 연도
- 주요 연혁 (있으면)
- 대표 인사말 (선택)

### 2-2. 실제 사업 실적 업종

메인의 "적용 가능 업종" 6종은 **제가 업계 표준으로 임의로 넣은 예시**입니다.

> 현재 표시 중: 전기전자·부품 / 자동차·부품 / 화학·소재 / 기계·금속가공 / 식음료·제약 / 포장·인쇄

**실제로 구축한 적 있는 업종**으로 바꿔야 합니다. 실적 없는 업종을 올려두면
문의 단계에서 신뢰를 잃습니다.

### 2-3. INFOLINK 플랫폼 상세

아키텍처 도면에서 모듈 구성은 파악했지만, `/solution` 페이지를 제대로 채우려면 더 필요합니다.

- 모듈별 주요 기능 (생산관리 / 품질 / 설비 / 물류 등)
- AI 기능이 실제로 어디에 적용되는지
- 타사 대비 차별점 중 **수치로 말할 수 있는 것**

### 2-4. 도입 절차와 소요 기간 ⭐

삼성SDS·LG CNS는 **"30년 경험"**으로 신뢰를 삽니다. 우리는 그 카드가 없습니다.
대신 **"어떻게 진행되는지 투명하게 보여주는 것"**이 신뢰 장치가 됩니다.
중소 제조사가 가장 불안해하는 지점이기도 합니다.

- 문의부터 오픈까지 단계 (예: 현황 진단 → 범위 확정 → 구축 → 검증 → 안정화)
- **단계별 대략의 소요 기간**
- 고객사에서 준비해야 하는 것 (담당자·설비 정보·네트워크 등)
- 최소 도입 단위 — "이 정도부터 시작 가능하다"

### 2-5. 자주 묻는 질문 답변 ⭐

경쟁사 조사에서 **LG CNS가 솔루션마다 FAQ를 붙이는 것**을 확인했습니다.
실적 자료가 없어도 만들 수 있고, 우리 포지셔닝("도입 장벽 낮추기")과 정확히 맞습니다.

제가 초안을 만들어 두었으니 **답변만 확인·수정**해 주시면 됩니다.

- 기존 설비가 오래됐는데 연결되나요?
- 최소 도입 비용·기간은 어느 정도인가요?
- ERP를 이미 쓰고 있는데 중복 아닌가요?
- 데이터는 어디에 저장되나요? (클라우드 / 자사 서버)
- 구축 후 유지보수는 어떻게 되나요?

### 2-4. 히어로 메인 문구 확정

3개 안을 만들어 두고 A안이 나오고 있습니다. **확정 필요**합니다.

| 안 | 문구 |
|---|---|
| **A (현재)** | MES 도입에 필요한 건 / **예산이 아니라 순서입니다** |
| B | 스마트팩토리는 대기업의 것이라는 말, / **이제 맞지 않습니다** |
| C | 대기업 MES를 / **중소 제조현장의 크기로** |

## 3순위 — 있으면 좋고, 없으면 섹션을 숨겨둡니다

### 3-1. 실적 수치

숫자를 보여주는 섹션을 만들어 두고 **꺼놓은 상태**입니다. 자료가 오면 켭니다.

- 설립 연도 / 누적 구축 프로젝트 수 / 고객사 수 / 임직원 수 / 연동 설비 대수

> ⚠️ 근거 없는 수치는 넣지 않았습니다. 이 업계는 문의 단계에서 바로 검증됩니다.

### 3-2. 구축사례

- 프로젝트별: 업종 / 적용 모듈 / 무엇이 어떻게 개선됐는지 한 줄
- **고객사명 공개 가능 여부** (계약상 비공개 조건 확인 필요)

### 3-3. 고객사 로고

역시 섹션만 만들어 두고 꺼놨습니다.

- 로고 이미지 파일
- **로고 사용 서면 동의** — 무단 게재는 실제 분쟁 사유입니다

### 4-1. 아키텍처 도면 오타 3건

이미지 안에 박힌 글자라 코드로 못 고칩니다. **원본 파일 수정 후 재전달** 필요합니다.

| 현재 | 수정 |
|---|---|

> 세 번째 도면은 사내 정보가 있어 공개에서 제외했으므로 급하지 않습니다.

### 4-2. 사진 자료 ⭐

현재 히어로·솔루션 이미지는 전부 **무료 스톡 사진**(Unsplash)입니다.
남의 사진이라 어느 회사 홈페이지에나 있을 수 있는 것들입니다.
**실물 사진 한 장이 스톡 사진 열 장보다 신뢰를 줍니다.**

우선순위 순으로 정리했습니다. 휴대폰 촬영도 충분합니다.

| 순위 | 무엇을 | 쓰이는 곳 | 요령 |
|---|---|---|---|
| **1** | **INFOLINK 실제 화면 캡처** | 솔루션 섹션 (지금 스톡 대시보드 사진 자리) | 대시보드·생산현황·설비모니터링 각 1장. 실제 데이터가 곤란하면 데모 데이터로 |
| **2** | **구축한 공장 현장** | 히어로 슬라이드, CTA 배너 | 설비·라인 전경. 고객사 식별 정보가 안 보이는 각도로 |
| **3** | **현장 단말 사용 장면** | 솔루션 "설비 데이터 수집" 블록 | 작업자가 PDA·태블릿·키오스크를 쓰는 모습 |
| **4** | **회사 로고 원본** | 전체 | 배경 투명 PNG 또는 AI/SVG 원본 (현재 배경 있는 PNG만 보유) |
| 5 | 사무실 · 팀 | 회사소개 | 있으면 좋음, 없어도 무방 |
| 6 | 대표님 사진 | CEO 메시지 (선택) | 인사말을 넣는 경우만 |

**촬영 시 참고**
- 가로 사진으로 (세로는 잘립니다)
- 가능한 한 밝게 — 사이트가 흰 톤이라 어두운 사진은 튑니다
- 원본 크기 그대로 주세요. 압축은 제가 합니다 (자동으로 30배 이상 줄입니다)

> ⚠️ **고객사 현장 사진은 촬영·게재 동의가 필요합니다.** 설비 배치나 제품이 보이면
> 영업비밀이 될 수 있어, 확실치 않으면 자사 데모 환경 촬영을 권합니다.

### 4-3. 회사 소개서 PDF

대기업 사이트를 조사해보니 **자료 다운로드**가 공통 장치였습니다

다운로드 버튼을 두면 두 가지가 생깁니다.
- 방문자가 사내 결재에 쓸 자료를 가져갈 수 있음

기존에 만들어 두신 **회사·솔루션 소개서 PDF**가 있으면 주세요. 없으면 나중에 만들어도 됩니다.

## 부록 · 대기업 사이트에서 확인한 것

삼성SDS와 LG CNS의 스마트팩토리 페이지를 분석했습니다.
두 곳이 공통으로 쓰는 신뢰 장치는 다음과 같았습니다.

| 장치 | 대기업 사례 | 우리 적용 |
|---|---|---|
| 실적 수치 | 삼성SDS: 생산성 15%↑, 셋업 50%↓ | 자료 확보 시 (3-1) |
| 경험 연수 | 양사 모두 "30년" | 해당 없음 → **절차 투명성으로 대체** |
| 제3자 인증 | Gartner · Forrester · IDC | 해당 없음 |
| **도입사례 PDF** | 다운로드 제공 | 소개서 확보 시 (4-3) |
| **FAQ** | LG CNS: 솔루션마다 배치 | **바로 적용 가능** (2-5) |
| **기술 사양표** | 삼성SDS: OS·DB·미들웨어 호환성 | **바로 적용 가능** — 아키텍처 도면에 자료 있음 |

> **핵심**: 대기업은 규모와 이력으로 신뢰를 삽니다. 우리에겐 그 카드가 없습니다.
> 대신 **"무엇을 어떻게 하는지 다 보여주는 투명성"**이 우리 크기에 맞는 신뢰 장치입니다.
> FAQ와 기술 사양은 실적 자료 없이도 지금 만들 수 있어 제가 먼저 반영해 두었습니다.

## 부록 · 받은 자료를 어디에 넣는가

*(사이트 재구성 이후 갱신 — 2026-09-01)*

지금 코드에는 **자료가 오면 바로 켜지는 자리**가 만들어져 있습니다.
값을 채우고 플래그만 바꾸면 관련 화면이 한꺼번에 나타납니다.
개발 환경(`npm run dev`)에서는 비어 있는 자리마다 무엇을 채워야 하는지 점선 상자로 표시됩니다.

| 받을 자료 | 넣는 곳 | 켜는 법 | 채우면 나타나는 곳 |
|---|---|---|---|
| 대표자명 · 사업자등록번호 · 주소 · **대표전화** | `content/site.ts` → `COMPANY` | 각 항목 `pending: false` | 푸터 · `/about` 사업자 정보 · `/contact` 전화 링크 · CTA 배너 전화 버튼 |
| 대표자 소개 (이름 · 직함 · 한 줄 경력 · **왜 만들었는지** · 사진) | `content/site.ts` → `CEO_PROFILE` | `pending: false` | `/about` LEADERSHIP 섹션 |
| INFOLINK 화면 캡처 | `public/images/` 저장 후 `content/site.ts` → `PRODUCT_SHOT` | `pending: false` | 히어로 첫 슬라이드 우측 (스톡 사진 대체) |
| 적용 사례 | `content/site.ts` → `CASE_STUDIES` 배열 | 배열 채우고 `SECTIONS.cases: true` | `/infolink` 맨 아래 CASE STUDIES 섹션 |

### 화면 캡처 사양

| | |
|---|---|
| 크기 | 가로 **1600px 이상**, 비율 16:10 권장 |
| 형식 | **PNG** — 화면 캡처를 JPG로 저장하면 글자가 뭉갭니다 |
| 내용 | 자주 쓰는 화면 1장 — LOT 추적 결과 / 재고 현황 / 작업지시 목록 중 |
| ⚠️ 주의 | **거래처명 · 담당자명 · 단가가 보이면 안 됩니다.** 데모 데이터로 다시 캡처하거나 해당 열을 가려 주십시오 |

### 적용 사례 카드에 들어갈 것

```
client   고객사명. 공개 동의를 못 받았으면 업종으로 (예: '자동차 부품 제조')
period   구축 기간
scope    8단계 중 어디까지 적용했는지
problem  무엇이 막혀 있었나   ← 카드에서 가장 먼저 읽힙니다
result   무엇이 가능해졌나
```

> ⚠️ `result`에 「30% 개선」 같은 수치를 쓰려면 근거가 있어야 합니다.
> 측정하지 않았다면 무엇이 가능해졌는지를 문장으로 적어 주십시오.

### 구축 방식 섹션 — 메인 페이지에서 가장 큰 공백

회사가 파는 것은 「구축」인데 그 과정이 사이트에 없습니다.
추측으로 쓰면 그 자체가 약속이 되므로 비워 두었습니다.

> **Q1.** 계약 후 오픈까지 어떤 순서로 진행하십니까? 단계 이름과 순서를 알려주십시오.
>
> **Q2.** 각 단계에서 인포패스가 하는 일과 고객사가 준비할 일을 나눠 주십시오.
> 특히 **품목·BOM·라우팅·검사기준을 누가 준비합니까?**
>
> **Q3.** 한 라인·한 품목으로 먼저 돌려보는 시범 운영 단계가 있습니까? 아니면 전체를 한 번에 오픈합니까?
>
> **Q4.** 가장 작은 범위로 시작할 때 보통 얼마나 걸립니까?
> 그 기간을 홈페이지에 적어도 되겠습니까? **적으면 약속이 됩니다.**
> ① 단계별 기간을 적는다 ② "최소 O개월부터" 하한만 ③ 기간은 안 적고 문의로 받는다
>
> **Q5.** 유지보수 범위와, 문의를 받으면 보통 며칠 안에 회신하십니까?

## 부록 · 구축 방식 섹션 — 답만 오면 바로 켜집니다

*(2026-09-01 추가)*

Q1~Q3의 답을 받으면 **코드 작성 없이 데이터만 넣으면** 메인에 나타납니다.
컴포넌트·레이아웃·문구는 이미 만들어져 있습니다.

**넣는 곳**: `content/site.ts` → `BUILD_STEPS`

```ts
export const BUILD_STEPS: ReadonlyArray<BuildStep> = [
  { id: 'diagnose', no: '01',
    title: '현황 진단',
    body: '공정 흐름과 지금 무엇을 어떻게 기록하시는지 확인합니다.',
    owner: 'infopath' },   // infopath | together | client
  // …
];
```

그리고 `SECTIONS.buildProcess: true`. **두 가지를 모두 해야 노출됩니다.**

### `owner`가 이 섹션의 값어치입니다

도입 검토자의 진짜 불안은 「얼마나 걸리나」보다 **「우리가 뭘 해야 하나」**입니다.
기준정보(품목·BOM·검사기준)는 고객사 데이터라 대신 만들어줄 수 없습니다.
그걸 `together`로 정직하게 밝히면 착수 후의 갈등을 미리 막습니다.
화면에서는 「함께」가 초록 배지로 눈에 띄게 표시됩니다.

### 확인용 초안 — 실제 절차가 아닙니다

아버지께 **이대로 맞는지만 확인**받으면 됩니다. 틀린 부분을 고쳐 주시면 그대로 넣습니다.

| | 단계 | 내용 | 주체 |
|---|---|---|---|
| 01 | 현황 진단 | 공정 흐름과 지금 무엇을 어떻게 기록하시는지 확인 | 인포패스 |
| 02 | 범위 결정 | 8단계 중 어디부터 시작할지 정함 | 함께 |
| 03 | 기준정보 정리 | 품목 · BOM · 라우팅 · 검사기준 · 창고 · 거래처 등록 | **함께** |
| 04 | 시범 운영 | 한 라인 · 한 품목으로 먼저 돌려봄 | 함께 |
| 05 | 확대 | 운영하면서 다음 모듈로 넓힘 | 인포패스 |

> ⚠️ **각 단계의 소요 기간은 확인 전까지 쓰지 마십시오.** 적는 순간 약속이 됩니다.
> 기간을 넣을지는 Q4에서 결정합니다.
